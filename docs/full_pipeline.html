Full Pipeline

Hallucination detection on FELM-Science: LLM confidence + Hidden Markov Tree + answer-level loopy belief propagation

Task and data

1Start with the actual task

The input is an LLM-generated answer from FELM-Science. Conceptually:

Question: Where is the Eiffel Tower located? Generated answer: “The Eiffel Tower was completed in 1889. It is located in Berlin. It is one of France’s most famous landmarks.”

The dataset gives us sentence-level factual labels. Our job is:

Determine which generated statements are hallucinated

We don’t simply classify the entire answer as True / False. We want a probability for each statement:

P(Z_i = T) where Z_i = T if statement is factual Z_i = F if statement is hallucinated

2First stage: dataset loading

The project uses the FELM Science data. Raw file: data/felm/all.jsonl. The project performs cleaning and constructs the Science subset. Final split used in the experiment:

SplitAnswersSentencesFalse
Total123595102
Fit6229153
Test6130449

The split is done at the answer level, not randomly at sentence level. This matters because sentences belonging to the same answer should not leak across train/test.

3Why do we split by answer?

Imagine Answer A: S1 “The Eiffel Tower is in Paris.”, S2 “It was completed in 1889.”, S3 “It is a famous landmark.” If S1 → training, S2 → testing, S3 → training, then the test sentence is still surrounded by almost identical contextual information. That’s undesirable. Instead:

Answer A → entirely TRAIN Answer B → entirely TEST

So our experimental unit is the answer rather than individual sentences.

Preprocessing

4Second stage: stand-alone sentence preparation

An important preprocessing step that can easily be missed. FELM contains segments that are sometimes context-dependent, for example:

“He was born there in 1950.”

If we feed that sentence alone to the confidence model, it doesn’t contain enough information. Who is “he”? What is “there”? So the project uses Llama to rewrite segments into standalone statements.

5What does rewriting mean?

Original answer: “Albert Einstein was born in Germany. He later moved to Switzerland.” The second segment, “He later moved to Switzerland.”, is context-dependent. We ask Llama to rewrite it using the question and complete answer context:

“Albert Einstein later moved to Switzerland.”

Extremely important constraint:

Don’t add or correct facts

The rewrite should preserve the original claim. We are changing expression, not factual content.

6How do we know the rewrite didn’t change the meaning?

We use NLI. Original O: “He later moved to Switzerland.” Rewritten R: “Albert Einstein later moved to Switzerland.” We test whether the rewritten statement entails the original:

R ⇒ O
  • R = rewritten sentence, O = original sentence
  • If NLI supports this, we keep the rewrite. If not, we retain the original.

The project reports: 594 segments considered for rewriting. Of those, 385 were rewritten and 122 were rejected (original kept for rejected cases).

7Why not simply rewrite everything?

Because an LLM rewrite can accidentally: add information, remove information, change a fact, or resolve an ambiguity incorrectly. Example. Original: “The company later expanded there.” Potential bad rewrite: “The company expanded to Germany in 2019.” The rewrite has introduced Germany and 2019, which weren’t in the original. That’s unacceptable. Hence:

rewrite + NLI validation

8Now we have a clean statement

Suppose our target statement is “The Eiffel Tower is located in Berlin.” Ground truth from FELM: Z = F. But our algorithm does not know this. That label is only used later for evaluation. This distinction is essential:

Algorithm: Evaluation: "The Eiffel Tower is located predicted probability in Berlin." ↓ ↓ compare with evidence ↓ ↓ ground-truth label probability

The ground truth must not enter the inference process.

Confidence and calibration

9Third stage: root confidence

Now we ask Llama for confidence. Conceptually the model is prompted to judge:

Is the statement true or false?

Suppose it produces token probabilities and our confidence score is:

P(True) = 0.03 P(False) = 0.97 S = P(True) / ( P(True) + P(False) ) = 0.03 / (0.03 + 0.97) S = 0.03

This is the observed confidence.

10Very important: S = 0.03 is not yet the final answer

A naïve system might say “Probability statement is true = 3%.” But that’s not our final probabilistic model. Why? Because the LLM’s confidence isn’t perfectly calibrated. We therefore transform it through the emission model.

11Fourth stage: confidence calibration

Our project uses logistic calibration:

P(T | S) = σ( a·logit(S) + b ) σ(x) = 1 / (1 + e^(−x)) logit(S) = log( S / (1 − S) )

The calibration parameters are fitted on the fit half. Our project reports:

a = 0.160, b = 1.160

using 291 fit-half sentences.

12Calculate it for S = 0.03

logit(0.03) = log(0.03 / 0.97) ≈ −3.476 a·logit(S) + b = 0.160(−3.476) + 1.160 = −0.556 + 1.160 = 0.604 σ(0.604) = 1 / (1 + e^(−0.604)) ≈ 0.647
P(T | S) ≈ 0.647

Notice something strange? The raw Llama confidence was 0.03, but the calibrated P(T | S) is around 0.65. That can look shocking.

13Why can this happen?

Because these two quantities are not the same thing. The calibration model is estimating P(T | S) from the empirical relationship between Llama scores and true labels. It is not simply rescaling 0.03 into another version of 0.03. The apparently surprising numbers arise because the fitted calibration is affected by the empirical base rate and the fit dataset. This is why we must distinguish:

S from P(T | S) and later from P(Z_r = T | S, tree)

14The emission model needs a likelihood

The HMT doesn’t directly use P(T | S) as its emission. It needs P(S | Z). Why? Because the graphical model is Z → S: the hidden truth causes the observed confidence. So we need:

P(S | T) and P(S | F)

15Bayes’ theorem gives the conversion

P(T | S) = P(S | T) P(T) / P(S) P(S | T) = P(T | S) P(S) / P(T) P(S | F) = P(F | S) P(S) / P(F)

The common P(S) term cancels in the final posterior. So the implementation can use proportional quantities:

p(S | T) ∝ P(T | S) / P(T) p(S | F) ∝ (1 − P(T | S)) / (1 − P(T))

The project uses P(T) = 0.5 as the base rate in the logistic emission. Therefore:

p(S | T) ∝ 2·P(T | S) p(S | F) ∝ 2·(1 − P(T | S))
Tree construction and exact BP

16Now the tree is built

Suppose our sentence contains multiple claims: “The Eiffel Tower was completed in 1889 and is located in Berlin.” There are two claims:

C₁ : “The Eiffel Tower was completed in 1889.” C₂ : “The Eiffel Tower is located in Berlin.”
R | decomposition / \ ▼ ▼ C1 C2

The hidden variables are Z_R, Z_C1, Z_C2.

17Why decomposition?

Because the truth of a multi-claim statement depends on the claims composing it. For this logical decomposition:

R = C₁ ∧ C₂ R = T ⇒ C₁ = T ∧ C₂ = T

But R = F doesn’t tell us exactly which child is false. Possibilities include (T,F), (F,T), (F,F), but not (T,T).

18The decomposition transition

For k = 2 children, if parent is true: P(T,T | R=T) = 1, and every other configuration gets 0. If parent is false, there are 2² − 1 = 3 non-all-true configurations, so each gets 1/3.

ParentChildrenProb

This is exactly the decomposition transition we derived earlier.

19Fifth stage: strategy selection

The project doesn’t decompose every statement endlessly. At a node, it determines whether decomposition is useful.

Statement | ▼ Does it contain multiple claims? | ├── No ──→ strategy | └── Yes | ▼ decomposition

Then the project can use logical relation reasoning or statement perturbation/correction, depending on the construction strategy.

20Logical Relation strategy

Parent: “The Eiffel Tower was completed in 1889 and is located in Berlin.” Decomposition children: (1) completed in 1889, (2) located in Berlin. Now we ask:

How do these child statements relate logically to the parent?

For each child, NLI compares child → parent and parent → child. This gives a relationship.

21NLI relationship types

The project uses:

{ equivalence, entailment, reverse entailment, contradiction, neutral }

Our example. Child: “The Eiffel Tower was completed in 1889.” Parent: “The Eiffel Tower was completed in 1889 and is located in Berlin.” The child does not entail the complete conjunction, but the parent entails the child. Therefore the relation is reverse entailment under the project’s direction convention.

22Why do we care about the relationship?

Because it determines P(Z_child | Z_parent). For reverse entailment:

P(C = T | R = T) = 1 P(C = T | R = F) = 0.5

So the NLI relationship becomes a probabilistic transition. This is where language understanding gets converted into a probability factor.

23The tree now contains both evidence and logic

R S_R = 0.03 | ┌──────┴──────┐ C1 C2 S_C1 = ... S_C2 = ... | | NLI relation NLI relation | | └──────┬──────┘ ▼ HMT inference

Each node has an observed confidence, and each edge has a logical relationship.

24Sixth stage: bottom-up belief propagation

Now we finally use the equation from Part 4. For a leaf:

β(z, u) = P(S_u | Z_u = z) If C1 is a leaf: β(T, C1) = P(S_C1 | Z_C1 = T) β(F, C1) = P(S_C1 | Z_C1 = F)

25Internal node equation

For the root:

β(z, R) = P(S_R | Z_R = z) · Σ_{z_c} P(z_c | z) · Π_c β(z_c, c)

For two children:

β(z, R) = P(S_R | Z_R = z) · Σ_{z₁,z₂} P(z₁, z₂ | z) · β(z₁, C1) · β(z₂, C2)

There are only 2² = 4 child assignments.

26Then calculate the root posterior

Once we have β(T, R) and β(F, R), we combine them with the root prior P(Z_R = T) = 0.5 and P(Z_R = F) = 0.5:

P(Z_R = T) = β(T,R)·0.5 / ( β(T,R)·0.5 + β(F,R)·0.5 ) The 0.5 factors cancel: P(Z_R = T) = β(T,R) / ( β(T,R) + β(F,R) )

That is the sentence’s tree posterior.

Answer-level graph and loopy BP (Extension 1)

27But we’re not done

This is where Extension 1 enters. Suppose the answer contains:

S1: The Eiffel Tower was completed in 1889. S2: The Eiffel Tower is located in Berlin. S3: The Eiffel Tower is a French landmark.

We have Tree₁, Tree₂, Tree₃. Each gives a root variable Z₁, Z₂, Z₃. Now we compare the sentence roots with NLI.

28Cross-sentence NLI

Consider S2 “The Eiffel Tower is located in Berlin.” and S3 “The Eiffel Tower is a French landmark.” These are related. But because NLI can generate false contradiction labels, our selected cross-link rule is:

no_contradiction

So contradiction links are discarded. Useful entailment-type links remain.

29Construct answer graph

Tree 1 | R1 | | R2 | Tree 2 | | R3 Tree 3

with cross-link factors ψ₁₂, ψ₂₃, etc. The complete answer is now a factor graph.

30The joint model

We can write the unnormalized distribution as:

P(Z | S) ∝ Π_i φ_i(Z_i) · Π_j ψ_j(Z_tree,j) · Π_{(i,k)∈E} ψ_ik(Z_i, Z_k)

Three types of information are now interacting:

  • Local evidence: φ_i
  • Within-sentence logical structure: ψ_tree
  • Across-sentence relationships: ψ_link

This is the full probabilistic model.

31Seventh stage: loopy BP

If the answer graph has no cycles, exact message passing can solve it. But if we have

R1 ── R2 | | | | R3 ────┘

we have a loop. Therefore loopy belief propagation is used.

32Start with uniform messages

Every message starts as m = (0.5, 0.5), meaning P(F) = 0.5 and P(T) = 0.5. No directional information has propagated yet.

33Factor → variable message

For factor f:

m_{f→v}(z_v) ∝ Σ_{z_f \ z_v} f(z_f) · Π_{u≠v} m_{u→f}(z_u)

So the factor combines (1) its logical relationship and (2) incoming beliefs from the other variables, and sends a new message.

34Variable → factor message

A variable combines all information except the target factor:

m_{v→f}(z_v) ∝ Π_{g∈N(v)\f} m_{g→v}(z_v)

This prevents immediate self-feedback.

35Repeat until convergence

The system repeatedly updates messages. For example:

Round 1 → Round 2 → Round 3 → ... → Round 24 → Δ < 10^-6 → Converged

In our real test: 122/122 answer graphs converged. Median ≈ 24 rounds. Maximum: 76 rounds.

36Final sentence posterior

After convergence:

b_i(z) ∝ Π_{f∈N(i)} m_{f→i}(z) Normalize: P(Z_i = T) = b_i(T) / ( b_i(T) + b_i(F) )

Now we finally have the quantity we wanted. For example: S1 → P(True) = 0.91, S2 → 0.22, S3 → 0.84. So the system identifies S2 as suspicious.

Evaluation

37Eighth stage: evaluation

Now, and only now, we compare predictions with FELM ground truth. The hallucination score is P(hallucination) = 1 − P(T).

38Then we evaluate the whole test set

For all 304 test sentences, we collect p̂_i = P(Z_i = T) and ground-truth labels y_i ∈ {0, 1}. Then calculate:

  • AUROC: measures ranking quality across thresholds.
  • AUC-PR: particularly useful because false examples are the minority.
  • F1: at a chosen classification threshold.

The tree model has AUROC = 0.741, which is slightly below raw Llama (0.745), but AUC-PR is 0.403 > 0.329. So AUROC alone doesn’t tell the entire story. The tree is substantially better in precision-recall space. Then the answer graph improves further: 0.403 → 0.475. This is why we report multiple metrics.

Extension 2 and the big picture

40Now put the surrogate into this pipeline

Our second extension changes the confidence stage. Instead of every node → Llama → S, we use:

Root Child ↓ ↓ Llama Surrogate ↓ ↓ S_root Ŝ_child

Then both enter the same HMT equations. So the inference code doesn’t change. Only the source of S_u changes.

42The entire project in one equation

At the highest level, our system is trying to estimate:

P(Z₁, …, Z_n | S₁, …, S_n, R, G)
  • Z_i = hidden truth of statement i
  • S_i = observed/model confidence
  • R = within-sentence logical relationships
  • G = cross-sentence NLI relationships

The factorization is approximately:

P(Z | S,R,G) ∝ Π_i φ_i(Z_i) · Π_j ψ_j(Z_tree,j) · Π_{(i,k)∈G} ψ_ik(Z_i, Z_k) confidence within-sentence cross-sentence evidence reasoning reasoning

and we estimate the desired marginals:

P(Z_i = T | S, R, G)

44What is the role of each probability?

There are several probabilities, and confusing them is one of the easiest ways to misunderstand the project.

  1. Llama token probability, e.g. P(True) = 0.03. This is model-token probability.
  2. Raw confidence: S = P(True) / (P(True) + P(False))
  3. Calibrated truth probability: P(T | S), obtained using σ(a·logit S + b)
  4. Emission likelihood: P(S | Z), used by the HMT.
  5. Final posterior: P(Z = T | all evidence). This is the actual output we care about.
